## 迭代 0（2026-08-12）— 项目奠基：文档先行

**目标**
重构版立项。先把需求、规则、架构、验收标准写清楚并可追溯，再进入编码；避免 v1（`CobeBriant/junqi-android`）
"规则埋在代码里、无法评审与追溯"的问题。本迭代**不产出游戏代码**。

**交付内容**
- GitHub 仓库：`https://github.com/CobeBriant/junqi-battle-android`（public）
- `README.md`：项目简介、两种玩法说明、文档索引、技术栈、规划目录结构、迭代纪律、与 v1 的关系
- `docs/PRD.md`：背景 / 目标与非目标（G-1..G-5）/ 目标用户与场景（U1..U3）/ 用户故事（US-1..US-10）/
  功能清单（F-01..F-15）/ **EARS 需求 41 条**（恒定 7、事件 12、异常 8、状态 6、可选 4，另含编号体系）/
  核心流程 / 交互说明（页面 P1..P6 + 棋子状态清单）/ 数据指标与埋点 / 验收标准（AC-1..AC-14）/
  边界与异常场景清单 / 待确认问题（Q-1..Q-7）
- `docs/规则说明.md`（规则唯一事实来源）：12×5 棋盘模型与坐标系、大本营/行营/兵站分布、铁路网与公路网
  （含行营斜线）、25 枚棋子与军衔表、**吃子判定表 12 组合**、公路/铁路走法与工兵转弯、
  翻棋细则、背靠背暗棋布阵约束（L-1..L-6）与裁判制揭示、胜负与判和、**6 个规则开关**、待复核项（D-1..D-4）
- `docs/ARCHITECTURE.md`：分层与模块（board/pieces/engine/ai/ui/app）、数据模型（Piece / GameState / Move / Battle）、
  引擎 API 契约 10 项、AI 三档设计与信息隔离约束、渲染与命中测试、测试策略五层、打包流程、风险与对策
- `docs/ROADMAP.md`：迭代 0–6 的目标 / 交付 / 退出标准 + 三个里程碑（M1 内核就绪、M2 可玩版、M3 首个发布版）
- `docs/迭代记录.md`：本文件与追加模板

**关键决策**
1. 技术选型沿用 v1：HTML5 Canvas + 原生 JS + Capacitor（纯前端可单测、打包链路已验证）。
2. 新建仓库而非续用 v1，v1 冻结作历史参考。
3. 规则不硬编码，全部走 `defaultRules` 开关，避免各地变体反复返工。
4. 信息隔离下沉到引擎 `viewFor(side)`，UI 与 AI 都拿不到不该看的数据。
5. 迭代 1 先做"连通图可视化自检页"，把棋盘几何风险前置消灭。

**测试结论**
本迭代无代码，无自动化测试。文档自检：文档间交叉引用一致（PRD 引用规则说明、ROADMAP 引用退出标准），
需求编号与功能编号无重复、无悬空引用。
