## 迭代 0（2026-08-12）— 项目奠基：文档先行

**目标**
重构版立项。先把需求、规则、架构、验收标准写清楚并可追溯，再进入编码；避免 v1（`CobeBriant/junqi-android`）
"规则埋在代码里、无法评审与追溯"的问题。本迭代**不产出游戏代码**。

**交付内容**

  功能清单（F-01..F-15）/ **EARS 需求 41 条**（恒定 7、事件 12、异常 8、状态 6、可选 4，另含编号体系）/
  核心流程 / 交互说明（页面 P1..P6 + 棋子状态清单）/ 数据指标与埋点 / 验收标准（AC-1..AC-14）/
  边界与异常场景清单 / 待确认问题（Q-1..Q-7）

  （含行营斜线）、25 枚棋子与军衔表、**吃子判定表 12 组合**、公路/铁路走法与工兵转弯、

1. 技术选型沿用 v1：HTML5 Canvas + 原生 JS + Capacitor（纯前端可单测、打包链路已验证）。

## 迭代 1（2026-08-12）— 规则引擎 + 连通图自检

**目标**
跑通规则内核：棋盘几何、走法、结算全部可信，且与已锁定的 Q-1/D-1/D-2 几何一致；通过可视化自检页与单测双重校验。

**交付内容**
- `www/js/board.js`：12×5 坐标系、特殊格位、铁路/公路邻接表（程序生成、运行期只读）。山界公路五列全通、铁路仅 c0/c2/c4 三桥、中线桥 `(5,2)↔(6,2)` 三桥连通，与 §1 完全一致。
- `www/js/pieces.js`：25 枚/方棋子与军衔表、军队生成、`resolveCombat` 吃子结算（炸弹/地雷/军旗/司令亮旗规则）。
- `www/js/engine.js`：对局状态机，实现 API 契约 `createGame / applyLayout / randomLayout / legalMoves / allLegalActions / applyAction / undo / viewFor / serialize / load`。信息隔离 `viewFor(side)` 下沉引擎层；规则集中在 `defaultRules`（含 `aiLevel` 等 7 项开关）。
- `www/debug.html`：连通图可视化自检页（SVG 绘制铁路/公路/行营斜线/山界，点击格高亮其公路相邻与铁路可达），供对照实体棋盘逐项核对。
- `test/engine.test.js`：18 项单测覆盖几何、12 组合吃子、铁路直行/工兵转弯、阻挡、行营保护、大本营锁定、布阵校验、夺旗/无路判负、视野隔离、悔棋、翻棋初始化。

**测试结论**
- `node --test`：**18/18 通过**。
- 连通图自检：铁路网三桥、山界五列公路、行营斜线均符合 `docs/规则说明.md §1`，自检页可人工比对。
- 额外冒烟：200 局随机自对弈（翻棋/暗棋各半）全部正常终止，无异常、无死循环（105 黑 / 95 红胜，0 未决）。
- 退出标准达成：单测全绿；几何已与规则说明核对一致（D-1/D-2 结论在 §1.3/§1.4 回写）；暗棋布阵校验正确拦截违规。

## 迭代 2（2026-08-12）— 两种玩法可玩（热座）

**目标**
不含 AI 也能在浏览器竖屏完整玩起两种玩法（翻棋 / 背靠背暗棋）。

**交付内容**
- 代码（新增 `www/`）：
  - `index.html` + `js/home.js`：首页与设置骨架，选玩法（翻棋/暗棋）、对战方式（热座已启用，AI 预留迭代 3）、规则弹层。
  - `layout.html` + `js/layout.js`：暗棋布阵页——点选兵种→点己方空格落子、拾起重摆、随机布阵、清空；实时校验 L-1..L-6；黑方确认后热座遮挡交接给红方。
  - `game.html` + `js/game.js`：主对局页 Canvas UI——选中高亮、合法落点（空格绿点/敌子红环）、上一手标记、战斗提示条、结算弹层、悔棋/重开/返回；翻棋可翻暗子或走明子，暗棋按 `viewFor(turn)` 仅显己方与已揭示敌子，每次换边弹热座交接遮罩。
  - `js/common.js` + `css/style.css`：共享棋盘渲染器（铁路/公路/行营/大本营绘制、像素↔格位映射）、存储与导航、移动端深色样式。
- 引擎补充：`applyAction` 战斗后依 `revealMode` 向双方揭示参战子（默认 `result`），更贴合热座直觉。
- 文档：ROADMAP 迭代 2 标记 ✅；ARCHITECTURE 升至 v0.3。

**关键决策**
1. 暗棋视野用 `Engine.viewFor(S, viewer)` 下沉实现，UI 不自行计算可见性，避免信息泄露。
2. 热座遮挡：暗棋每换边强制"请交接设备"遮罩，设备不离手也不泄露对方布阵。
3. 翻棋保留引擎既定"明翻"语义（棋子开局即随机归属某色，翻子仅揭示），与迭代 0 锁版规则一致。

**测试结论**
- 单元测试 + 集成测试：22 项全部通过（`node --test`，含双布阵整局自对弈、视野隔离、战斗揭示、悔棋回退、序列化往返）。
- 前端冒烟：用 DOM/canvas 桩加载全部页面脚本，零初始化报错；ID 与事件绑定已交叉核对。
- 浏览器真机视觉验证：待用户侧确认（本机无 GUI 浏览器）。

## 迭代 3（2026-08-12）— 单机 AI（三档）

**背景**：迭代 2 已实现两种玩法热座，但单人无法游玩。本迭代补齐 AI 对手，使一人即可对战。

**交付物（代码 `www/`）**
- `js/ai.js`（约 210 行）：`chooseAction(state, side, level)` 三档决策 + `evaluate` 评估函数。
  - `easy`：随机但偏向吃子/翻子（抽到可吃则吃）。
  - `normal`：1 层启发式评估——子力价值（军衔）+ 位置（攻防推进）+ 公平战斗期望，胜率按军衔表估算；曾翻开的敌子按其身份评估，未翻开的暗子按 `unknown` 价值（≈30）估算，绝不读取其真实身份。
  - `hard`：对 top-K 走法（K=8）做 2 层搜索，对手用其自身视野反制（对手视角下我方暗子同样未知），含时间上限（约 600ms）截断。
  - 信息隔离强保障：`VALUE`/`evaluate` 仅依赖 `viewFor(side)` 等价可见信息，测试 `no peek` 断言全暗敌子下不崩、返回合法。
- `index.html` + `js/home.js`：对手可选「人机对战」，AI 模式下显示难度（简单/普通/困难），URL 传 `opp=ai&level=&side=black`。
- `js/layout.js`：AI 模式仅人类（黑方）布阵，自动为 AI（红方）随机布阵后 `beginPlay` 进入对局。
- `game.html` + `js/game.js`：AI 回合循环（人类行动后 `setTimeout` 调度 `chooseAction` 并落子、战斗提示、结算）；AI 模式下 `viewer` 固定人类视角（隐藏 AI 暗子）、不显示热座交接遮罩、增加「思考中」指示。

**测试**
- `test/ai.test.js`（6 项）全绿：三档/两玩法下返回合法行动；`no peek` 断言；normal「不送子」针对性用例；normal vs easy 多局自对弈胜率 = 10/10（>90%）；1000 局混合自对弈必然终局无异常。
- 全量 `node --test`：**28/28 通过**（含迭代 1/2 既有用例）。
- DOM/canvas 桩加载全部页面脚本（含 `ai.js`）：零初始化报错。

**关键修复**
- `cloneState` 初版 `JSON.parse(JSON.stringify(state))` 会克隆含 `history` 的整个状态，长对局下 OOM；改为只克隆活动字段（`pieces/board/turn/phase/movesSinceBattle/revealMode/rules/result`），模拟态丢弃悔棋链。

**退出标准达成**：✅ 普通档对随机档胜率 10/10（>90%）；✅ 人机无长时间卡顿（思考 200–900ms 分片）；✅ 自对弈无死循环。

**遗留问题 / 下一步**
- [ ] 用户侧实玩：选「人机对战」试三种难度手感（建议本地静态服务器）。
- [ ] 迭代 4：存档/悔棋增强/阵型库；迭代 5：视听打磨；迭代 6：签名 APK。
